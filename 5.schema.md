# SkillBridge — Database Schema (MongoDB)

Design principle: **domain-as-config**. The engine (Assessment, Gap, Matching) is domain-agnostic; AYUSH is data loaded into these collections, not hardcoded logic. A new domain (e.g. Engineering) is added by inserting `Domain` / `SkillCategory` / `Skill` documents — no code change.

## Domain & Skill Taxonomy

### `Domain`
```
{
  _id,
  name: String,                // "AYUSH", "Engineering"...
  slug: String,
  description: String,
  isFlagship: Boolean,         // true for AYUSH at launch
  createdAt, updatedAt
}
```

### `SkillCategory`
```
{
  _id,
  domainId: ObjectId → Domain,
  name: String,                 // "Clinical/Procedural", "Regulatory", "Research", "Soft Skill"
  description: String
}
```

### `Skill`
```
{
  _id,
  domainId: ObjectId → Domain,
  categoryId: ObjectId → SkillCategory,
  name: String,                          // "Panchakarma Technique", "GMP & Regulatory Basics"
  description: String,
  proficiencyScale: {                    // configurable, not hardcoded per component
    beginner: [0, 39],
    developing: [40, 59],
    intermediate: [60, 74],
    advanced: [75, 89],
    expert: [90, 100]
  },
  curriculumReference: String | null,    // generic field: e.g. "NCISM BAMS Syllabus Unit 4"
                                          // populate only with a source you can actually cite
  assessmentTypesSupported: [String]     // ["mcq", "rubric", "video"]
}
```

## Users

### `User`
```
{
  _id,
  role: "student" | "industry" | "institution" | "academician" | "ministry" | "admin",
  name, email, passwordHash,
  phone, preferredLanguage,
  domainId: ObjectId → Domain,           // primary domain of interest
  profile: { ... role-specific subdocument, see below },
  isVerifiedAccount: Boolean,
  createdAt, updatedAt
}
```
Role-specific `profile` subdocuments:
- **student:** `{ institutionId, program, year, careerInterests[], targetRoles[] }`
- **industry:** `{ organizationName, sector, verifiedByAdmin: Boolean }`
- **institution:** `{ institutionName, region, verifiedByAdmin: Boolean }`
- **academician:** `{ institutionId, subjectArea, researchInterests[] }`
- **ministry:** `{ department }` (read-only role, admin-provisioned)

## Skills & Assessment

### `SkillResult` (a student's state for one skill)
```
{
  _id,
  studentId: ObjectId → User,
  skillId: ObjectId → Skill,
  status: "claimed" | "assessed" | "verified" | "needs_improvement",
  score: Number,                          // 0–100
  verificationSource: "self-declared" | "college-verified" | "platform-assessed",
  lastAssessedAt: Date,
  history: [ { score, status, assessedAt } ]   // for progression charting
}
```

### `Assessment`
```
{
  _id,
  skillId: ObjectId → Skill,
  type: "mcq" | "rubric" | "video",
  questions: [ { text, options[], correctOptionIndex } ],   // for mcq
  rubricCriteria: [ { criterion, maxScore } ] | null,       // for rubric/video type
  durationMinutes: Number
}
```

### `AssessmentAttempt`
```
{
  _id,
  studentId: ObjectId → User,
  assessmentId: ObjectId → Assessment,
  answers: [...],
  rawScore: Number,
  normalizedScore: Number,          // 0–100
  submittedAt: Date
}
```

## Opportunities & Applications

### `Opportunity`
```
{
  _id,
  industryId: ObjectId → User,
  domainId: ObjectId → Domain,
  title: String,
  type: "internship" | "job" | "apprenticeship" | "live_project" | "challenge" | "training" | "workshop" | "mentorship",
  description, eligibility,
  requiredSkills: [ { skillId, minProficiency: Number } ],
  location: String, isRemote: Boolean,
  durationWeeks: Number,
  status: "open" | "closed",
  createdAt
}
```

### `Application`
```
{
  _id,
  studentId: ObjectId → User,
  opportunityId: ObjectId → Opportunity,
  status: "saved" | "applied" | "under_review" | "shortlisted" | "interview" | "selected" | "rejected" | "started" | "in_progress" | "completed",
  matchResultSnapshot: { ... },      // MatchResult captured at time of application
  appliedAt, updatedAt
}
```

### `MatchResult` (computed, not necessarily persisted long-term — snapshot on application)
```
{
  overallScore: Number,             // 0–100
  breakdown: {
    skillCompatibility: Number,
    assessmentPerformance: Number,
    eligibility: Number,
    relevantExperience: Number
  },
  matchedSkills: [ { skillId, studentScore, requiredScore } ],
  gapSkills: [ { skillId, studentScore, requiredScore, gap } ]
}
```

## Learning

### `LearningResource`
```
{
  _id,
  skillId: ObjectId → Skill,
  title, url, type: "article" | "video" | "course" | "practice_project",
  estimatedHours: Number
}
```

## Collaboration (Academician ↔ Industry/Institution)

### `CollaborationOpportunity`
```
{
  _id,
  postedById: ObjectId → User,      // industry or institution
  type: "fdp" | "guest_lecture" | "mentorship" | "research" | "live_project",
  title, description,
  domainId: ObjectId → Domain,
  status: "open" | "closed",
  interestedAcademicianIds: [ObjectId → User]
}
```

## Feedback

### `Feedback`
```
{
  _id,
  applicationId: ObjectId → Application,
  givenById: ObjectId → User,       // mentor/recruiter
  ratings: { technicalSkills: Number, communication: Number, problemSolving: Number },
  comments: String,
  createdAt
}
```

## Analytics (precomputed snapshots — see techspec.md §5 performance note)

### `InstitutionAnalyticsSnapshot`
```
{
  institutionId: ObjectId → User,
  domainId: ObjectId → Domain,
  generatedAt: Date,
  totalStudents: Number,
  avgReadiness: Number,
  skillGapSummary: [ { skillId, avgScore, gapCount } ]
}
```

### `MinistryAnalyticsSnapshot`
```
{
  domainId: ObjectId → Domain,
  generatedAt: Date,
  byInstitution: [ { institutionId, avgReadiness, topGaps: [skillId] } ],
  nationalSkillGapSummary: [ { skillId, avgScore } ]
}
```

## Indexing notes
- `SkillResult`: compound index on `{ studentId, skillId }` (unique).
- `Opportunity`: index on `{ domainId, status }`.
- `Application`: compound index on `{ studentId, opportunityId }` (unique), plus `{ opportunityId, status }`.
- `AssessmentAttempt`: index on `{ studentId, assessmentId, submittedAt }`.
