# SkillBridge — Design Guidelines

## 1. Design brief
- **Subject:** an evidence-based skill readiness platform, government-adjacent (Ministry of Ayush / SIH), flagship domain is AYUSH (Ayurveda, Yoga, Unani, Siddha, Homoeopathy).
- **Audience:** students (many from Tier-2/3, vernacular-medium colleges), industry recruiters, institution admins, and government/NCISM reviewers.
- **Primary job of the homepage:** make the lifecycle (`Claim → Assess → Verify → Match`) instantly legible, and feel credible and calm rather than like a generic startup SaaS template — this is closer to institutional trust (a passport, a certificate) than a consumer app.
- **Brief constraints from the client:** animated 3D homepage, clean and exactly understandable UI/UX, light and elegant colors.

## 2. Design token system

### Color (light, elegant — deliberately not the common AI-generated defaults)
| Token | Hex | Role |
|---|---|---|
| `--bg-porcelain` | `#F7F6F2` | Base background — warm off-white, not stark white or cream-with-terracotta |
| `--ink` | `#1D2420` | Primary text — near-black with a quiet green undertone, not pure black |
| `--pine` | `#21463D` | Primary brand / CTA / "Verified" state — deep, elegant pine-teal |
| `--slate` | `#3C4A66` | Secondary structural color — institution/ministry sections, links |
| `--ochre` | `#B9863C` | "Claimed / In progress" state — muted gold, used sparingly |
| `--rust` | `#A85338` | "Gap / needs improvement" state — deliberately muted and darker than the common AI-cliché terracotta, used only for this one meaning |
| `--mist` | `#E4E8E2` | Borders, dividers, subtle surfaces |

Color carries **meaning, not decoration**: pine = verified, ochre = in progress, rust = gap. This mapping should be consistent everywhere a skill status appears, so a returning user reads state by color instantly.

### Type
- **Display/headline:** a humanist serif with quiet gravity (e.g. Fraunces, optical size set low for elegance) — signals institutional trust without being a stiff broadsheet serif.
- **Body/UI:** a clean grotesk (e.g. Inter or General Sans) for legibility in dense dashboards.
- Two typefaces only, clearly distinct roles. No monospace for data labels — proficiency numbers are set in the grotesk with tabular figures.
- Line length under 80 characters for body copy.

### Layout
- Homepage hero: **asymmetric**, left-aligned headline block + right-side 3D animation. Not center-stacked, not a full-bleed generic gradient hero.
- Dashboards: flat bordered panels (`1px solid var(--mist)`), no drop shadows, no uniform rounded-corner "SaaS card kit" look. Border radius used sparingly and consistently (one scale, not ad hoc).
- Alignment: left-aligned content throughout (data-heavy product — center alignment would hurt scanability).

### Principles
1. Every number on screen is explainable — no orphaned percentages.
2. Color encodes skill state consistently across the whole product.
3. One deliberate motion moment on the homepage; everywhere else, motion only responds to user action.
4. Never look like a job board — no listing-heavy, card-grid-of-everything homepage.

## 3. The animated 3D homepage — concept

**Hero animation ("The Skill Graph"):** on page load, a small cluster of abstract nodes (representing claimed skills, in `--ochre`) drift together in 3D space and resolve into a connected passport/seal shape, shifting color to `--pine` as they "verify" — a literal, one-time visualization of the product's core promise. Built with React Three Fiber; runs once on load, does not loop indefinitely, does not react to scroll/hover (per the single-orchestrated-moment principle — avoid scattered fade-ins on every section).

- Duration: ~2.5–3s, then settles into a static, still-elegant final frame that anchors the hero copy.
- `prefers-reduced-motion: reduce` → skip straight to the static final frame (a clean SVG/illustration), no animation triggered.
- Keep the 3D scene's own palette restricted to the token set above — no default Three.js blues/greens outside the brand palette.

**Below the hero:** the lifecycle band (`Claim → Assess → Gap → Learn → Verify → Match → Apply`) as a horizontal connected-node strip — numbering/sequence markers are justified here because the content genuinely is a sequence.

## 4. Component patterns
- **Skill status pill:** color-coded per token above (`Verified` / `In progress` / `Needs improvement`), consistent shape everywhere.
- **Skill gap visualization:** a radar/spider chart per role comparison, using `--pine` for the student's actual profile and a light `--mist`-shaded polygon for the required threshold.
- **Explainable match card:** shows the overall score plus a short per-skill breakdown list (✓/⚠), never the score alone.
- **Empty states:** written as an invitation to act ("No assessments yet — claim your first skill to see your readiness"), not a generic "No data."

## 5. What to avoid (explicitly, per known AI-generated-design tells)
- Warm cream background + terracotta accent combo (common generated default).
- Near-black background with a single neon accent.
- Uniform rounded-corner cards with identical soft grey shadows everywhere.
- Tracked-out ALL-CAPS eyebrow labels, middle-dot meta strings, spaced-em-dash labels, arrow-suffixed buttons ("Learn more →").
- Scattered fade-and-slide-up entrance animation on every section — the homepage gets exactly one orchestrated motion moment.

## 6. Accessibility & responsiveness
- WCAG AA contrast minimum for all token pairings (verified: `--pine` on `--bg-porcelain` passes; `--ink` on `--bg-porcelain` passes).
- Full keyboard navigation, visible focus states.
- Responsive: mobile-first for the student flow specifically (many students will access via phone on limited bandwidth) — the 3D hero should degrade gracefully to a lightweight static asset on low-power/mobile devices, not just on `prefers-reduced-motion`.
