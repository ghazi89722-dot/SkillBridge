# SkillBridge — Implementation Plan

## Guiding rule
Build one true end-to-end story first (see PRD §8 success metric), then widen. Never let a role's dashboard get more build time than the core loop until the loop works live.

## Phase 0 — Setup (few hours)
- Repo scaffold: Next.js frontend, Express backend, shared TypeScript types package (optional).
- MongoDB Atlas cluster + Mongoose connection.
- Auth: signup/login + JWT + RBAC middleware skeleton for all 6 roles.
- Seed script: one `Domain` ("AYUSH"), 2–3 `SkillCategory`, ~10 `Skill` documents with realistic AYUSH names and clearly-sourced-or-labeled `curriculumReference`.
- Base design tokens wired into Tailwind config (colors/type from design.md).

## Phase 1 — Core MVP loop (bulk of hackathon time)
Build in this order, each step demoable before moving to the next:
1. Student signup/onboarding → claim skills against seeded AYUSH skill list.
2. Assessment Engine: MCQ-type assessment for at least 4–5 skills, scoring → `SkillResult` (status `assessed`).
3. Skill Gap Engine: define one sample `Opportunity` ("Panchakarma Therapist Intern") with required skills/thresholds; compute and display gap.
4. Learning recommendation: static curated links per gapped skill.
5. Reassessment flow: student retakes assessment → score updates → status recalculates (`verified` / `needs_improvement`).
6. Digital Skill Passport page: renders verified skills with provenance tags.
7. Matching Engine: deterministic formula, explainable breakdown, ranked opportunity list for the student.
8. Industry side: opportunity creation form, ranked candidate list with breakdown, shortlist action.
9. Application state machine wired end to end (`applied → under_review → shortlisted → selected`).

**Exit criterion for Phase 1:** the exact demo script in PRD/appflow.md runs live without manual data fudging.

## Phase 2 — Institution, Ministry, Academician layers
- Institution dashboard: aggregate readiness, skill-gap trend view (precomputed snapshot job).
- Ministry dashboard: cross-institution aggregation, read-only role, heatmap view.
- Academician collaboration module: CRUD + browse/request flow.
- Post-internship feedback form feeding back into `SkillResult` history.

## Phase 3 — Polish & differentiators
- Animated 3D homepage hero (React Three Fiber) per design.md, with `prefers-reduced-motion` fallback.
- Micro-internship / short-task listing type on `Opportunity`.
- Tele-internship credit workflow (supervised remote hours logging) — design only if time-constrained, build if time allows.
- DigiLocker/NAD verification integration research spike (does not need to be functional for the pitch, but a clear "how we'd wire this in" diagram strengthens Q&A).
- Accessibility pass (contrast, keyboard nav, reduced motion).
- Add a second domain's seed data (even minimal) as a live proof that the schema is genuinely domain-agnostic — strong differentiator in judging.

## Suggested hackathon time-boxing (36–48h window)
| Block | Focus |
|---|---|
| Hrs 0–4 | Phase 0 setup |
| Hrs 4–20 | Phase 1, steps 1–6 |
| Hrs 20–32 | Phase 1, steps 7–9 (this is the differentiator — protect this time) |
| Hrs 32–40 | Phase 2 (institution + ministry dashboards minimum) |
| Hrs 40–46 | Phase 3 homepage polish + bug fixing |
| Hrs 46–48 | Demo rehearsal, slide deck, buffer |

## Definition of "demo ready"
- No hardcoded/faked scores shown as if computed — every number traces to real seed data and real formula execution.
- At least one full before/after reassessment story with real numbers.
- Homepage loads and the 3D hero animation completes cleanly on the demo machine (test on the actual presentation hardware beforehand).
